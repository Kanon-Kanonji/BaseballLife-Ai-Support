== はじめに
本プログラムは、野球選手育成ブラウザゲーム『Baseball Life（以下BBL）』のゲームロジックおよび環境をPython上で疑似的に再現するシミュレータである。

本シミュレータは、選手状態、行動可能条件、各行動によるステータス遷移、確率イベントおよび時間進行を管理する。AIによる行動選択や画面表示には依存せず、同一のルール実装を強化学習やGUIから共通利用できる構成とする。

本設計書は、BBL再現シミュレータを構成する各モジュールの責務および操作仕様を定義する。

=== 対象範囲

本シミュレーターの対象範囲を以下に示す。

* 選手およびゲーム内環境の状態保持
* 行動可能条件の判定
* 指定された行動による状態遷移
* 確率イベントの抽選
* シーズン（オン／オフ）・年齢の進行
* 行動結果の返却

以下は本シミュレーターの対象外とし、別設計書で定義する。

* Gymnasiumの``action_space``および``observation_space``
* AI向け観測値への変換
* 報酬および育成結果の評価
* エピソードの管理
* 強化学習アルゴリズムおよびモデル訓練
* GUI関連

=== 再現方針

本シミュレーターは、BBLの完全再現ではなく、育成上の意思決定に必要な主要ルールの再現を目的とする。

集中率・オウム出現率など公に公開されていない値はグローバル定数へ直接固定せず、シミュレーター生成時に設定オブジェクトとして注入可能な構成とする。

== 共通インターフェース

=== BBLAction

``BBLAction``は、シミュレーターへ指定できる最終選択肢を表す固定の``IntEnum``とする。

``練習``や``恋愛``等の画面上の親カテゴリは``BBLAction``へ含めない。練習内容、購入品、取得球種等の対象まで確定した一つの操作を一つのEnum値として定義する。

``BBLAction``の値および意味はプレイヤー状態によって変更してはならない。学習済みモデルとの互換性を維持するため、既存値の採番変更および再利用を禁止し、新しい行動は末尾へ追加する。

想定する行動区分を以下に示す。

[cols="2,4,4", options="header"]
|===
|行動区分 |Enumの単位 |例

|練習
|練習項目と練習種別（大／小）の組ごと
|``PRACTICE_MEET_LARGE``

|自主トレ
|主催・参加および対象項目ごと
|``JISYUTORE_HOST_MEET``

|勉強
|勉強対象ごと
|``STUDY_<TARGET>``

|遊び
|使用する遊び道具ごと
|``PLAY_<ITEM>``

|公園
|公園への外出で一つ
|``GO_TO_PARK``

|恋愛
|出会う相手、デート、プロポーズおよびフィットネスごと
|``DATE``、``PROPOSE``

|ダンジョン
|取得対象アイテムごと
|``DUNGEON_<ITEM>``

|各施設
|注文または施設利用の最終選択肢ごと
|``BUY_YAKITORI``、``GO_TO_LABORATORY``

|買い物
|購入アイテムごと
|``BUY_<ITEM>``

|能力取得
|取得球種または特殊能力ごと
|``LEARN_PITCH_<PITCH>``、``LEARN_SPECIAL_<ABILITY>``

|日程進行
|半年の進行で一つ
|``MOVE_NEXT_TERM``
|===

練習項目、アイテム、球種および特殊能力の全マスタが確定した後、完全なEnum一覧と採番を定義する。

=== ActionDefinition

``BBLAction``ごとの実行情報は``ActionDefinition``として固定のカタログに保持する。

[source,python]
----
@dataclass(frozen=True)
class ActionDefinition:
    action: BBLAction
    category: ActionCategory
    target_id: str | None
    variant: str | None
    consumes_action_count: bool
----

行動回数を消費するか否かは、呼出経路ではなく``ActionDefinition``によって明示する。これにより、買い物や能力取得等を練習と同じ実行窓口から安全に扱う。

=== ActionResult

``ActionResult``は、一回の操作による状態遷移を表す。

[source,python]
----
@dataclass(frozen=True)
class ActionResult:
    action: BBLAction
    before: PlayerState
    after: PlayerState
----

報酬や育成結果の評価値は``ActionResult``へ含めない。上位の評価モジュールが``ActionResult``を入力として計算する。

== マスタデータおよび設定

=== bbl_masterモジュール群

本モジュール群は、``resources``フォルダ内のCSV等を読み込み、シミュレーター内で参照する型付け済みの不変データを生成する。

CSVは原則として起動時に一度だけ読み込み、行動ごとにファイルを再読込しない。ファイル形式の検証、必須列の確認、重複IDの検出および値域検証も本モジュール群で行う。

初期開発で管理する主なデータを以下に示す。

* 能力値と経験点の対応表
* 成長型および年齢ごとの補正値
* 変化球一覧
* 特殊能力一覧
* アイテム一覧
* 行動定義

``const``として想定していた値のうち、ゲーム仕様として固定された表データはマスタデータとして管理する。集中率等の推定値や実行ごとに変更する値は``SimulatorConfig``として分離する。

=== resourcesフォルダ

``resources``にはマスタデータの原本を配置する。各レコードは表示名とは別に、変更しない一意なIDを持つ。

学習済みモデルおよび保存データとの互換性へ影響するため、既存IDの意味の変更および別用途への再利用を禁止する。

=== SimulatorConfig

``SimulatorConfig``は、推定値、仮定値、乱数に関する設定および機能の有効・無効を保持する。

[source,python]
----
@dataclass(frozen=True)
class SimulatorConfig:
    concentration_rate: float
    parrot_rate: float
    gap_success_rate: float
----

具体的な設定項目、既定値、値域および仕様確度は、設定値一覧の作成時に定義する。

=== bbl_simulatorモジュール群
本モジュール群ではBBLの進行を管理する。
行動回数を消費する行動に加え、買い物、能力取得および日程進行等の状態変化を統括する。

本モジュール群はゲームルールの実行窓口であり、GUI上の画面遷移、AIの観測生成および報酬計算は行わない。

=== bbl_rulesモジュール群

本モジュール群は、BBLの計算規則および判定規則を提供する。

原則として、入力された状態、マスタデータおよび設定値から計算結果を返す。CSVの読込、プレイヤー状態の保持、画面表示および報酬計算は行わない。

==== practice_calc.py

本モジュールは、練習による経験点の増減および練習に付随する確率判定を統括する。

野手固有の計算は``fielder.py``、投手固有の計算は``pitcher.py``へ委譲する。共通する成長型補正、AP補正、アイテム効果および設定値の適用順序は、本モジュールの詳細設計時に定義する。

==== fielder.py

本モジュールは、野手に関する能力値と経験点の対応表等を読み込み、保持する。

経験点の計算は``practice_calc.py``が行い、本モジュールは計算を行わない。

ただし、マスタデータの読込および保持を``bbl_master``へ分離する方針と重複するため、``fielder.py``は``bbl_master``配下の野手用カタログへ移動する候補とする。配置および名称はマスタデータ設計時に確定する。

==== pitcher.py

本モジュールは、投手に関する能力値と経験点の対応表等を読み込み、保持する。

経験点の計算は``practice_calc.py``が行い、本モジュールは計算を行わない。

ただし、マスタデータの読込および保持を``bbl_master``へ分離する方針と重複するため、``pitcher.py``は``bbl_master``配下の投手用カタログへ移動する候補とする。配置および名称はマスタデータ設計時に確定する。

==== common.py

本モジュールは、複数のルールから使用する共通の計算および判定を提供する。

単なるマスタデータ取得は``bbl_master``の責務とする。本モジュールへ無関係な処理が集中しないよう、責務が独立した時点で専用モジュールへ分割する。

==== calc_init.py

本モジュールは、選手生成時の初期能力を計算する。

成長型、ポジション、アピールポイント、転生元から引き継ぐ条件およびマスタデータを入力とし、初期能力の計算結果を返す。具体的な入力項目と計算式は未定義とする。

==== reset.py

本モジュールは、選択されたアピールポイントに応じて、選手の能力経験点および状態の初期値を生成する。

``bbl_simulator.reset.py``は次世代へ移行する全体手順を管理し、``bbl_rules.reset.py``は能力経験点および行動状態等の初期値生成のみを担当する。

``calc_init.py``との責務が重複する可能性があるため、両モジュールの具体的な入力と出力を整理した後、統合または改名を判断する。統合する場合は、責務を表す``player_initializer.py``等の名称を候補とする。
